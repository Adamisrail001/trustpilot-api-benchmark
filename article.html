Best Trustpilot Reviews API in 2026: I Tested 5 So You Don't Get Stuck at 200 Reviews

I benchmarked 5 Trustpilot review APIs against a manually verified dataset to find out which ones actually break past the 200-review wall.

Picture this: you ship a Trustpilot review pipeline for a client dashboard. It works in the demo — 200 reviews, clean JSON, done. Three months later, someone notices a business with thousands of reviews on Trustpilot still shows the same 200 it did on day one. Nobody flagged an error. The job just stopped growing.

That's the trap most "Trustpilot API" comparisons gloss over. Every landing page shows a clean request and response. None show you what happens on review #201, or what a "SUCCEEDED" status is quietly hiding.

So I stopped reading marketing pages and built a benchmark instead: 5 Trustpilot review APIs, the same 5 real businesses, every result checked against a manually verified ground-truth sample, each API pushed past its comfort zone to find the actual wall. Not which API has the prettiest docs — which one you can build a pipeline on without getting silently capped.

Why not just use Trustpilot's own API?

Trustpilot does have official APIs — Business Units, Product Reviews, and Service Reviews cover a business's own profile and review data, and a separate Data Solutions API can return review data across businesses. That should have made it a contender. It never made it into the benchmark, and the reason isn't what you'd expect.

The Business APIs require a Trustpilot for Business account with API module access via Trustpilot's developer portal. Public endpoints use an apikey header and paginate with a pageToken, but exclude fields like the reviewer's email or order ID. The fuller private version, and the cross-business Data Solutions API, mean registering on a waitlist and waiting for Trustpilot's team, with OAuth 2.0 setup either way — not signing up and shipping a request an hour later.

[SCREENSHOT: Trustpilot Data Solutions "get started" page showing the waitlist sign-up copy]

I excluded it during pre-screening, before any live testing, because it failed the one requirement every API here had to clear first: self-serve access. I never obtained credentials, and no benchmark run exists for it. This was an access limitation, not a capability failure — Trustpilot's own APIs can retrieve review data fine, including across businesses. They just don't let you start testing today, on your own, the way every third-party API here does.

How I picked the 5 APIs I tested

I searched API marketplaces, developer docs, search results, and Reddit threads, then narrowed a much longer list on 6 pass/fail criteria: self-serve access (a working key without a sales call), testability (can it run the actual workload), usable documentation, computable cost, platform coverage (does it return Trustpilot data at all), and active availability.

Trustpilot's official API failed the first criterion (above). What survived all 6: lobstr.io, DataForSEO, Outscraper, Apify, and OpenWeb Ninja.

How I tested them

Same workload for all 5: up to 200 reviews per business, across 5 Trustpilot businesses — The Pearl Source, SHEIN, Temu, AliExpress, Halara — for a 1,000-review target per provider.

The main benchmark ran July 21–29, 2026. I reran DataForSEO, Apify, Outscraper, and lobstr.io live on August 13 to confirm the numbers held. OpenWeb Ninja wasn't part of that rerun — its dashboard has no quota-check endpoint, so rerunning it risked burning quota against a result I couldn't interpret; its last verified run is what's reflected here.

For data quality, I needed a source of truth that wasn't just "API A agrees with API B" — so I manually verified a 20-row sample from The Pearl Source (author names, ratings, reply text, dates) and compared every API's output against it field by field. That covers 1 of the 5 businesses; I don't generalize its accuracy numbers to the other 4, and neither should you.

Each provider was tested across 6 categories: reliability, data quality & coverage, cost efficiency, speed & throughput, scalability, and developer experience. A 7th original-rubric category, input flexibility, is folded into data quality & coverage and discussed under each API's developer-experience notes, where it actually affects you. I'm not compressing those into a single weighted score in this article — lobstr.io was the only provider that could complete a full review-collection job, so scoring it against tools capped at 200 reviews per business on data volume, speed, or cost wouldn't be a fair comparison. What follows is what each API actually delivered, category by category.

One disclosure: this benchmark was run and written by lobstr.io's own content team, and lobstr.io is one of the providers tested. Nothing I found looked suppressed or inflated in its favor — but weigh the conclusions with that in mind. Full raw evidence is public: github.com/Adamisrail001/trustpilot-api-benchmark.

  • Accuracy: all 20 ground-truth rows matched by author name, with 6 field-level differences on 2 of the 13 fields — not zero, but not a coverage gap either (see freshness below).

Worth mentioning APIs

The rest of the APIs I tested hit the same 200-review-per-business ceiling, so I'm not weighing them against each other on that front. Two of them are still worth knowing about for specific reasons: DataForSEO for its price, and Apify for its developer ecosystem and integrations.

DataForSEO

API type: Async (task-based)  ·  Best for: lowest-cost collection when 200 reviews/business is enough

DataForSEO is worth mentioning for one reason above all: price. It has the lowest measured cost in the benchmark, at $0.03754 per 1,000 successful reviews — but a confirmed 200-review ceiling per business.

What is DataForSEO?

DataForSEO is a data-API provider covering SEO and business data at scale, with a dedicated Trustpilot Reviews endpoint. You post a domain to a task queue, poll until it's ready, then pull the result.

Features

  • Review collection by business domain
  • depth parameter for how many reviews to request per task; sort_by (e.g. recency)
  • Task-based async workflow: task_post → tasks_ready → task_get

Data quality

  • Field coverage: 84.6% (11 of 13) — the narrowest schema of the 5; review_type (invited vs. organic) and useful_count (helpful-vote count) don't exist anywhere in it.
  • Accuracy: 20/20 ground-truth match by author name, 0 confirmed mismatches on every field it does capture.
  • Schema consistency: 0 missing-field occurrences across all 1,000 raw items.
  • Freshness: unlike lobstr.io and Outscraper, 0 field-level drift surfaced this run.
  • Data usefulness: clean and consistent, if you don't need helpful-vote counts or invited/organic flags.

Pricing

  • No free tier; $50 minimum account funding; published rate $0.00075/review
  • Actual cost per 1,000 successful reviews: $0.03754 — taken directly from the cost field on every task_post response. Measured and billed, not an estimate — cheapest of all 5 by a wide margin.
[SCREENSHOT: DataForSEO task_post response JSON showing the cost field]

Speed

165,513 ms (about 2 min 46 s) for 1,000 reviews — fastest of the original benchmark. A live rerun on August 13 told a different story: ~421,200 ms total serially, about 2.5x slower under that day's queue conditions. Data and cost were unaffected — a speed-only regression, still nowhere near DataForSEO's documented worst-case SLA of "up to 45 minutes."

Reliability

999 of 1,000 unique reviews (99.9%), 0 HTTP errors across 10 requests. The one missing review: Temu's task returned the same review twice in its own response — an internal duplicate, not a dropped request.

Scalability

This is DataForSEO's real ceiling, and it's not ambiguous: the Trustpilot reviews endpoint has no page, offset, or skip parameter at all. 200 reviews per business is the documented, current maximum — a confirmed hard cap with no pagination route around it, not an untested gap.

Developer experience

API-key auth worked first request; every documented parameter matched live behavior, no debugging required. The trade-off is flexibility — one domain string per call, no array/batch, no enrichment endpoint. No SDK; docs show curl examples only.

Pros
  • Cheapest measured cost of all 5, by a wide margin
  • 99.9% completion with 0 HTTP errors
  • Documentation matched live behavior with zero discrepancies
Cons
  • Confirmed 200-review-per-business ceiling, no pagination workaround
  • Single-domain input only — no batching or arrays
  • Measured speed regression on rerun (still within documented SLA)

Verdict

Choose DataForSEO if cost is the deciding factor and 200/business covers your use case — nothing else here is this cheap. Avoid it if you need deeper collection; there's no pagination parameter to reach for. It's worth mentioning for price and reliability alone, held back only by a hard ceiling it doesn't hide.

Apify

API type: Async (Actor run)  ·  Best for: developer experience and ecosystem flexibility, with your own completeness check

Apify is worth mentioning for its developer ecosystem — its actor marketplace plugs into a wide range of tools, including AI and automation platforms, which is part of its appeal beyond the raw benchmark numbers below. However, my testing found that a successful run does not always mean every requested business returned data.

What is Apify?

Apify is an actor-based automation platform — you run pre-built "Actors" through a unified run/dataset API. Its Trustpilot data comes from the automation-lab/trustpilot Actor.

Features

  • Review collection by company URL, accepted as an array — multiple businesses in one run
  • maxReviewsPerCompany (docs say 0 means unlimited; this benchmark tested 1000, not 0 — see Scalability); includeCompanyInfo flag embeds company name, Trust Score, category
  • Retry/error-classification logic (401/403/402 → auth/billing; 400/404 → invalid request; 429/500–504 → retryable)

Data quality

Apify's weak point: across 3 separate live runs, one business returned 0 reviews every time — a different business each time (SHEIN, then The Pearl Source, then Halara), always a clean SUCCEEDED status with zero error signal.

  • Field coverage / accuracy / freshness: not stable enough to quote — 92.3% when The Pearl Source (the ground-truth business) succeeds, 0% when it's the run's silent failure. Neither number is Apify's real accuracy.
  • Data usefulness: on runs that do return data, the fields are usable; the instability itself is the actual finding here, not a field gap.
[SCREENSHOT: Apify run object showing status: "SUCCEEDED" next to a dataset item count of 0 for the affected business]

Pricing

  • Free: $0/month, $5 credit; Starter $29/month; Scale $199/month; Business $999/month; published rate $0.005/run + $0.000575/review
  • Actual cost per 1,000 successful reviews: $0.5812 — $0.465 total, read directly from the run's own usageTotalUsd field. Real and billed, just for fewer successful reviews than requested (800 of 1,000, because of the silent-failure issue above).

Speed

402,134 ms total (about 6 min 42 s) — median 2,022 ms, p95 2,874 ms. Concurrency was explicitly set to 1, so this says nothing about behavior under real parallel load.

Reliability

80% overall success on the committed run (800/1,000 raw and unique, 0 duplicates), with the silent-failure pattern landing at 79.8–82% across all 3 live attempts — every occurrence a SUCCEEDED status, zero error signal.

Scalability

Testing maxReviewsPerCompany=1000 against a single business returned exactly 200 unique reviews, 0 duplicates, with the Actor's own pagination_stop_reason reporting all_items_downloaded — Apify itself considered the job complete at 200. Its docs separately claim maxReviewsPerCompany=0 means unlimited; that configuration wasn't tested, so this isn't proof of a universal limit. What's confirmed: requesting 1,000 doesn't get you more than 200 in this tested configuration.

Developer experience

Auth worked first attempt, and the retry/error-classification logic is real and documented. The problem is what it doesn't catch: a run that silently returns zero results for one business while reporting success. Building on Apify means adding your own completeness check.

Pros
  • Strong developer ecosystem and flexible actor-based tooling
  • Real, measured billing figure ($0.5812/1,000), not an estimate
  • Genuine retry/error-classification logic for real HTTP failures
Cons
  • Confirmed recurring pattern: a different business silently returns 0 reviews across 3 runs, always reporting SUCCEEDED
  • Ground-truth data quality isn't a stable, quotable figure because of that pattern
  • Confirmed 200-review ceiling in the tested configuration

Verdict

Choose Apify if ecosystem flexibility and tooling matter most — just don't trust its SUCCEEDED status alone; add a row-count check first. Avoid it if you need dependable per-business completeness without babysitting the output. The unresolved silent-failure pattern is the main reason it's in the worth-mentioning list rather than the top pick, not any single weak category.

lobstr.io is the only API here that collected every review it was asked for — 1,000/1,000 on the standard test — and the only one confirmed past Trustpilot's 200-review-per-business wall, verified at 2,000/2,000 unique reviews with 0 duplicates.

FAQ

Which API is cheapest?
DataForSEO, by a wide margin — $0.03754 per 1,000 reviews, a measured billing figure, not an estimate.

Which API is fastest?
DataForSEO's committed wall-clock time (165.5 seconds for 1,000 reviews) was fastest, though a live rerun measured roughly 2.5x slower under that day's queue conditions — still within its documented SLA.

Which API can collect more than 200 reviews from one business?
Only lobstr.io, confirmed — 2,000/2,000 unique reviews, verified live August 13. DataForSEO, Outscraper, and Apify are all confirmed capped at 200; OpenWeb Ninja is untested past 200.

Which API had the best data quality?
lobstr.io, outright — 100% field coverage (13/13 ground-truth fields) against the ground-truth sample, ahead of Outscraper at 84.6% (11/13). Both show the same explainable field-level drift on the fields they share.

What about Outscraper?
Outscraper performed reliably in this benchmark — 100% completion with 0 errors, reproduced on a live rerun, and tied lobstr.io for the best field coverage at 92.3%. Its Trustpilot endpoint hits the same 200-review-per-business ceiling as DataForSEO and Apify: requesting limit=1000 against The Pearl Source returned exactly 200 items, even though that response's own total_reviews field reported 17,586 reviews exist for that business. Combined with the highest price tested (an estimated $2.70–$3.00 per 1,000 reviews), that's why it isn't in the worth-mentioning list above.

What about OpenWeb Ninja?
I tested OpenWeb Ninja's Trustpilot endpoint because an earlier pass looked promising: 1,000/1,000 reviews returned cleanly, 100% ground-truth match, broad field coverage. That didn't hold. A verification run on the same account returned 0 of 1,000 reviews across all 5 businesses, with 75 HTTP 429 errors over roughly 37 minutes of retry waves that never cleared. The likely explanation is account- or quota-side, not a platform-wide regression — but I couldn't confirm that, so I'm not recommending it for a production build right now.

Which API is best overall?
lobstr.io — the only provider confirmed past the 200-review wall, while also holding up on data quality, reliability, and cost. See the disclosure above before treating that as gospel.

Why wasn't Trustpilot's official API included?
It failed this benchmark's self-serve access requirement before any live testing — both the standard Business APIs and the Data Solutions API require Trustpilot-side approval or a waitlist, not instant signup. An access limitation, not a sign the official API can't retrieve reviews.

Is scraping Trustpilot reviews legal?
Trustpilot's consumer and business Terms of Use both bar "text mining, data mining or web scraping" without express permission. In the US, hiQ Labs v. LinkedIn found that scraping publicly accessible data doesn't itself violate the CFAA — but LinkedIn still won on breach-of-contract grounds, and hiQ was permanently enjoined and shut down. A platform's own terms can create real legal exposure even where anti-hacking law doesn't apply. Not legal advice — check your jurisdiction before collecting or using Trustpilot data commercially.
