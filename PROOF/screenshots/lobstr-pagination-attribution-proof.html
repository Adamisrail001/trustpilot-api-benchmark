The item carries a run ID (which task-run produced it) but no task field (which input/business it belongs to) — undocumented. When a single run covers multiple businesses (as this benchmark's 5-domain run did), attributing a result back to its source domain requires falling back to matching company_page_url against the input domain list, not a documented, direct field lookup.
Scope note: both gaps are documentation-vs-behavior mismatches on Lobstr's own API, not benchmark-harness bugs — see IMPORTANT/knowledge.md:393–394 for the sourced write-up these screenshots back.
