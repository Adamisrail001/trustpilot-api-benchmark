Apify — retry & error classification logic

How the benchmark's own client wrapper sorts Apify's HTTP responses into fatal-auth, fatal-invalid, and retryable buckets before deciding whether to back off and try again.

Classification rules

Auth / billing 401 · 403 · 402 — raises AuthOrBillingError, no retry
Invalid request 400 · 404 — raises InvalidRequestError, no retry
Retryable 429 · 500 · 501 · 502 · 503 · 504 — exponential backoff, up to MAX_RETRIES = 3
